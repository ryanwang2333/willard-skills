# research：先查可靠资料，再给带来源的结论

当用户想"查清楚一个问题"，或需要准确、权威的信息（文档、接口、事实、最新版本），而不是靠记忆随口答时使用本技能。

## 做法

1. **只信可靠来源**：优先官方文档、源代码、规范、第一手 API——而不是二手转述。结论尽量追到"拥有它的"最上游出处。
2. **能并行就并行**：如果环境支持派子代理去后台查证，就派出去，不让用户干等；不支持就直接查。
3. **输出带引用的浓缩结论**：整理成一份 Markdown 或结构化的中文小结，每条关键结论**标注来源链接**。
4. **诚实标注**：查不到的、不确定的，明确写"未能查证/受时间或权限所限"，不要编造。

## 使用时机

- 用户问事实类、文档类、接口类、版本类问题
- 用户说"帮我查一下 / 研究一下 / 这个功能怎么用"
- 任何不该靠记忆、应该查证才能答准的领域性问题
