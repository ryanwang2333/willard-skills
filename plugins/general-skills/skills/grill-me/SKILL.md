# grill-me：动手前先把需求问清楚

当用户要开始一项任务、计划或想法，而目标、范围、形式、标准仍有含糊之处时，使用本技能**主动、分轮地追问**，直到双方对"要做什么、做到什么、做到什么程度"达成共识，再动手。用户也可以主动要求触发。

## 核心方法：把需求想成一棵「决策树」

- 树的每个节点 = 一个待定的决定。
- 一个决定定下来，才会展开依赖它的下一层决定。
- 目标：把这棵树的所有分支都走完，不留任何"静默假设"。

## 按「轮」推进，一轮问清"当前层"

- **锋线（frontier）** = 当前所有"前置条件已确定、可以问"的决定。
- 每一轮**一次性把整条锋线的问题全部问出来**，不要一个问题一个问题挤牙膏。
- 每轮结束，等待用户的回答，再根据回答**重新计算锋线**，进入下一轮。依赖本轮仍未定问题的那些问题，归入后续轮次，不要在本轮提前问。

## 提问格式（固定用法）

每条问题给编号、标题、说明，并附上你的**推荐答案**，方便用户快速选择或否决：

```
❌ 问题 1：<一句话点题>
<说明，可多行，可列举多个选项>

- 🗳️ 我的推荐：<你的建议>
```

## 三条纪律

1. **查证是你的工作，不是用户的**：需要查文件、环境、数据等事实时，用你自己的工具去查（必要时可派子代理并行查），不要为你能查到的事反过来问用户。**真正留给用户的，是"决定"**。
2. **同一轮内，不追问依赖本轮其他问题答案的问题**——它属于之后的轮次。
3. **结束信号**：决策树锋线清空、没有悬而未决的假设时，先复述你对共识的理解，**等用户确认后再开始动手**，不要直接开干。

## 触发时机

- 用户提出一个任务，但范围、受众、形式、验收标准模糊
- 用户说"先问清楚""帮我理理思路""我拿不准""这个想法你觉得可行吗"
- 一个请求有多种合理理解，选错会白干或返工

符合上述任一情况（且你已决心动手之前）时，优先调用本技能先追问一轮。
