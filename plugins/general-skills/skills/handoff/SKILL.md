# handoff：会话收尾 + 交接

当一段会话要结束、之后会换新会话继续同一件事时，执行收尾工作流：不留烂尾任务、记忆不丢关键结论、工作区干净、下个会话能无缝接续。

## 1. 盘点未完成任务

- 检查 `TaskList`，确认有无 in_progress / pending 任务。
- 未完成项处理：要么当场完成，要么明确"留给下个会话"并写进交接摘要。**不要默默留下悬空任务。**

## 2. 更新记忆（重要但克制）

- 找出本会话**值得跨会话保留**的信息：新结论、环境事实变更、用户偏好、项目状态。
- **只记重要的、无法从文件系统/工具重新推导的**。记忆不是百宝袋——不要什么都塞。
- 优先**更新已有记忆文件**，而非新建；确有必要才新建。同步更新 `MEMORY.md` 索引行。
- 已过时/已废弃的记忆条目要删除或标记废弃（删除走 CLAUDE.md 常驻的删除授权规则）。

## 3. 检索并清理工作区

- 检查工作区各区域：工作目录、临时目录、项目根目录下的测试/调试残留。
- 对每个文件分类：**正式交付物 / 测试残留 / 临时文件 / 占位文件**。
- 清理无用文件（遵守删除授权流程）：可写区直接 rm；只读挂载区走授权。保留正式交付物、有回查价值的副本。
- 删前确认无保留价值，并说明删了什么、为什么。

## 4. 写交接文档

写一份简洁的交接文档：

- **做了什么、进行到哪、卡在哪、下一步该做什么**。
- 加一个"**建议调用的技能**"清单，方便下次会话按需触发。
- 关键决定保留结论；已交付的细节（代码、方案、文件）**引用文件/链接**即可，不重复粘贴。
- **脱敏**：API 密钥、密码、个人敏感信息绝不写进文档。
- 存到当前工作区，并明确告诉用户文件路径，方便日后接管。

## 5. 给收尾摘要

给用户简洁的收尾总结：

- **本会话完成了什么**（几件大事）
- **清理了什么、留下了什么**
- **悬而未决事项**（列出留给下个会话的 todo）
- **下个会话从哪继续**（一句可执行的话）

## 使用时机

- 用户要结束工作、之后离开或换会话
- 用户担心"换个会话就丢了进度"
- 用户说"收尾 / 整理成交接 / 下次接着做 / 开新窗口继续"
- 长会话自然结束时

## 纪律

- 记忆只存"不可重新推导"的重要事实，克制，不堆砌。
- 删除走授权流程，不硬删、不反复试错。
- 交接要具体可执行，让下个会话无需重新探索环境。
